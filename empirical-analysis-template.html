Empirical Analysis Template

GitHub

A self-contained R + LaTeX template for a single-study empirical paper. It provides the analysis-pipeline scripts, data-source adapters, a paper template, and figure and table style conventions. Put your data in data/, run main.R, and write up in LaTeX/. It is built to be used by hand; an AI agent is optional.

Structure

All folder names are lower-case except LaTeX/.

  • data/: datasets/ holds the anonymised raw exports (tracked, so everything rebuilds from GitHub); raw_SENSITIVE/ holds anything with identifiers and is gitignored. The cleaned dataset sits at the root of data/ as CSV and RData, next to README.md and CODEBOOK.md.
  • scripts/: config_init, config_toolkit (shared plotting, table and number-formatting helpers), config_cleaning, sample_restrictions, balance_table, descriptives, hypotheses, robustness, exploratory, plus further_analysis/.
  • scripts/helper/: pluggable data-source adapters (otree.R, csv.R).
  • LaTeX/: paper source. Figures and tables land in LaTeX/output/{figures,tables}/. Every number quoted in the text goes into one values file, LaTeX/output/values.{tex,json}, and the paper prints it with \val{name}. A .latexmkrc routes build files to .build/, so the folder stays clean and self-contained.
  • literature/: papers and reading notes.
  • flow/: codebook, research log, timeline, to-do list and project profile, plus the skill files skill_graphs.md, skill_tables.md and lessons_from_mistakes_paper.md. They work as a style guide for you and as reference material for an AI agent.
  • feedback/: referee reports, seminar comments and meeting notes, named meetings_YYYY-MM-DD.md.
  • DECISIONS.md: project decisions, newest first, each with date and reason.
  • _ai/: scratch space for an AI agent. Gitignored.

Conventions

  • Sensitive data check: a pre-commit hook in .githooks/pre-commit refuses any commit that contains Prolific IDs, emails, IP addresses, user agents or identifying CSV columns. Turn it on once per clone with git config core.hooksPath .githooks.
  • House style: the paper front matter sets 1in margins and \onehalfspacing.
  • Reporting: bar charts of means with ±1 SE whiskers, booktabs tables run as one block with no panels, and p-values to three decimals with the test and sidedness stated.
  • One output folder: all outputs go to LaTeX/output/, with no per-study subfolders.

Getting started

Clone the repository to get a working copy:

git clone https://github.com/juliantait/Template_Analysis.git

If you work with an AI agent, the CLAUDE.md at the repository root is its entry point: it points the agent at the conventions and the project state in flow/. For how I use Claude in a project folder, see AI Workflow in My Project Folder.

Sync to Overleaf

Sync sends the entire LaTeX/ folder, including the R-generated output/ folder of figures, tables and the values file, up to a new Overleaf project as a git push. After the initial push, future git push overleaf main:master from inside LaTeX/ ships subsequent edits; git pull overleaf master brings collaborator changes back.

Sync to Overleaf

  1. Create a new empty project in Overleaf (web UI).
  2. In the project sidebar, open Integrations → Git and copy the project's git URL, for example https://git.overleaf.com/<project-id>.
  3. Inside the LaTeX/ folder, init a git repo if needed: cd LaTeX && git init. The LaTeX folder becomes its own working tree, independent from the outer repo.
  4. Add Overleaf as a remote and push: git remote add overleaf <overleaf-git-url> && git push -u overleaf main:master. Overleaf has historically used master as the default branch; if main:master is rejected, run git ls-remote overleaf to see the actual branch name.
  5. Subsequent edits: git push overleaf main:master from inside LaTeX/. Collaborator changes from Overleaf come back via git pull overleaf master.

Overleaf's git integration is a premium feature, available on paid individual or group subscriptions and to Overleaf Commons participants. Free-plan projects will not show a Git option in Integrations.

Full Overleaf-side guide: docs.overleaf.com: Git integration.
