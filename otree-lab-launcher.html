What it does

You have an oTree study that runs on your own machine. Getting it running across a room of lab PCs is the fiddly part. Three things have to be set up before a session can start:

  • A Postgres database. Created and pointed at.
  • The participant list. Loaded in.
  • An experiment room. Defined so each seat connects to the right session.

The Lab Launcher does all of that for you. Point it at any working oTree project and it sets up Postgres, the participant lists and the experiment room, then starts the server ready for the room to connect.

How it works

Everything that is specific to your lab lives in one file:

  • lab_info.json. A gitignored file holding the settings the launcher needs: database credentials, the host address, which study is running. Nothing lab-specific is committed to the experiment repository, so the same project moves between labs by swapping that one file.
  • maps/. Room layouts sit alongside it, one map per room, describing which seats exist and how they are labelled.

The first time you run the launcher, a setup wizard fills all of this in for you. It walks through the questions once, writes lab_info.json and the room maps, and from then on launching is a single click.

Once the server is running, each lab PC opens its own per-seat link, one URL per desktop that puts that participant in their seat in the experiment room: 

http://HOST:8000/room/study?participant_label=SEAT

You place that link on each desktop once, with HOST, the study name and the seat's SEAT label filled in from the room map. After that the operator clicks launch and the room is ready.
