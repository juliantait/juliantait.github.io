oTree Template

GitHub

An oTree template for running experiments in the lab and online.

  • A participant flow, built and styled — with an adaptable payment rule.
  • Lab and Prolific from one setting — the same study, recruited either way.
  • Three screening layers — comprehension, device, and tab-switching for web studies.

Bring your instructions & game, and you are ready to run.

App timeline

A session moves through the four apps in order:

  • before — landing page, welcome message, and informed consent.
  • intro — task instructions followed by a comprehension quiz.
  • main — the experimental task you build yourself; the app arrives empty and takes your game pages, including any treatment-specific ones.
  • outro — demographic questionnaire, debrief, and the earnings tracked for that participant, together with the bank details a lab session needs to pay them later.

How to use it

Clone the repository to get a working copy:

git clone https://github.com/juliantait/Template_oTree.git

A root CLAUDE.md records the rules an agent must not break and why each exists, alongside per-job authoring guides in docs/skills_claude/, so an LLM working in the repository starts with its conventions loaded rather than guessing at them.

Then edit the files relevant to your experiment. The intended entry points are:

  • Instructions — edit intro/instructions_text.html. Each <div class="instruction-block"> renders as one participant page.
  • Comprehension quiz — define quiz items (prompt, choices, correct answer) in intro/quiz_items.py.
  • Treatment assignment — set up your conditions in before/treatment_assignment.py. Treatments are assigned at session creation via creating_session in the before app.
  • Game — build your economic game in the main app. Add any HTML pages for the game to this app, and configure the app settings (rounds, decisions, payoffs) in main/__init__.py.
  • Earnings rule — outro/payment_rule.py ships a working default that pays up to N randomly chosen rounds, drawing on the payoffs your game produces; replace it with your own if your study pays differently.

Lab and online from one codebase

One setting chooses whether the study runs on Prolific or in the lab, and everything else follows from it.

Running on Prolific

  • Straight in from the Prolific link — the ID it carries is recorded, and the participant lands in the study without seeing the entry gate.
  • Three screening layers — comprehension, device and tab-switching, with a completion code per route, so a screened-out participant stays distinguishable from one who finished.
  • Earnings tracking — what the participant has earned is kept in a single ledger, under a payment rule that pays up to N randomly chosen rounds by default and can be replaced with your own.
  • Ready to deploy — a Dockerfile that runs on Railway or TreeHost.
  • Checked before it ships — tests including visual layout checks, a pre-deploy run of the new build against a copy of the live database, and a boot guard that will not wipe existing data.

Running in the lab

  • Straight in from the seat link — an arrival carrying a seat's ID passes the entry gate without seeing it, and lands in the study itself.
  • Bank details and demographics — collected in the outro app alongside the debrief, so the session can be paid afterwards.
  • Earnings tracking — what the participant has earned is kept in a single ledger, under a payment rule that pays up to N randomly chosen rounds by default and can be replaced with your own.

The experimenter can watch participants move through the session and see how far each of them has got. What an experimenter needs to know sits on one page, rather than being pieced together from several.

Previewing instructions

See example

Working on instruction copy inside a running server is awkward, so the template ships a preview generator that renders your instructions as standalone files — an interactive page you click through like a participant, and instructions_preview.pdf to send a coauthor for comment.

Shared visual scaffold

All apps inherit a shared HTML/CSS layer that gives sessions a consistent look without per-app styling. The reference layout lives at _static/global/html/template.html and demonstrates the standard card layout used across pages — header, body content, and a navigation footer. Extending or restyling the experiment is a matter of editing this one template and the accompanying stylesheet.

Making oTree data usable

Download script Full analysis template on GitHub

An R script that reshapes oTree's wide session CSVs into long format (one row per participant × app × round), pre-configured for the variable names used in this template. It is one helper from the Empirical Analysis Template — a self-contained R + LaTeX pipeline for a single-study empirical paper.
